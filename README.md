# Chess Vault · TanStack preprod

Ветка `preprod` содержит перенос интерфейса на React 19, TypeScript и TanStack Start в SPA-режиме. Рабочая версия GitHub Pages остаётся в `main`.

## Запуск

```sh
npm ci
npm run build
npm run typecheck
npm test
npm run test:store
npm run preview
```

Собранное приложение: http://localhost:4173. Разработка: `npm run dev`. Статическая публикация: `.output/public`. Нужны SPA fallback на index.html и заголовки COOP/COEP; `_redirects` и `_headers` входят в сборку. Stockfish и сети скачиваются скриптом с проверкой контрольных сумм. Бинарники не хранятся в git.

React управляет всеми экранами и доской. Чистые вычисления `src/domain` сохранены без изменений и проверяются на совпадение с исходной версией. Типизированное хранилище `src/services/store.ts` публикует снимки через useSyncExternalStore. Старый `dist` сохранён только как проверяемая база миграции; новый сайт его не использует как оболочку.

Стили прежнего приложения сохранены в base.css для визуальной совместимости, новые локальные стили используют CSS Modules. Расчёты домена пока остаются JavaScript с типизированными границами; их перевод в TypeScript можно делать независимо от рендера.

## Безопасное тестирование

- Отдельный origin, метка PREPROD, localStorage `chess-vault-preprod-v3`, отдельный manifest и префикс кэша.
- Никакого автоматического импорта или изменения production-данных. В профиле можно импортировать копию JSON и экспортировать тестовые сохранения.
- Прямые ссылки на профиль, коллекцию и архив работают через SPA fallback.
- Активная партия закрывает доступ к другим экранам. Итоговая доска остаётся до закрытия результата.
- Архив начинается с нулевого хода, поддерживает ручные переходы и старт/паузу.
- Новые партии используют Stockfish 19 smallnet; старые профили движка сохранены.

## Проверки и публикация

`.github/workflows/preprod.yml` собирает Start, проверяет TypeScript, правила/миграции, транзакции хранилища и сценарии Playwright в Chromium/WebKit. Готовый artifact называется preprod-static, браузерные результаты — browser-results. Workflow не публикует рабочий GitHub Pages.

Тестовый сайт публикуется отдельно через Sites. Последующие коммиты preprod проходят CI; публикация Sites выполняется отдельно, автоматической связи GitHub push → Sites в этом репозитории нет.

Перед переносом в main ещё требуется ручная приёмка на реальном iPhone/PWA, проверка сценария обновления production и переключение конфигурации окружения/публикации. В частности, старый pages.yml пока относится к старому production — не сливать ветку для выпуска без отдельной настройки release.
