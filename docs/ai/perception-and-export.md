# Ограниченный расчёт, пропуск мата и экспорт PGN

## Интеграция

До этого изменения пропуск найденного мата исключал матующие ходы, но сохранял loss относительно мата. Категории почти всех оставшихся ходов становились blunder, и fallback выбирал лучшую нематующую альтернативу. Теперь после пропуска относительные потери пересчитываются внутри оставшегося пула. Выбранный ход возвращается с исходной объективной оценкой: отчёты не скрывают ухудшение, входные данные не мутируются.

Ранний полный MultiPV-снимок глубины не выше 2 берётся из того же потока UCI, что глубокий анализ. Дополнительных поисков нет. Используются только совпадающие ходы, CP-оценки и строго более глубокий финальный снимок. Если раннего полного снимка нет или он содержит mate scores, механизм ограниченного расчёта для него не применяется. Для каждой стороны оценки остаются относительно стороны хода.

После обычного выбора и защиты может быть выбран внешне приемлемый вариант, если:
- shallowLoss <= 0.90 пешки;
- объективный loss от 0.90 до 3.00;
- глубокий loss хуже неглубокого минимум на 0.50;
- вариант хуже уже выбранного минимум на 0.50;
- нет признака прямой потери крупной фигуры;
- в позиции не активирована обработка мата в 1–2.

Вероятность такого пропуска = 0.45×(1−skill)^2. Выбор внутри пула взвешен exp(−shallowLoss). Это ограниченная модель расхождения оценок, не распознавание человеческих мотивов «связка» или «перегрузка». Исходная гипотеза shallowLoss<0.4 находила преимущественно позиционные неточности. Порог 0.9 и минимальное расхождение 0.5 позволили выделить несколько действительно ухудшающихся продолжений. Добавлена проверка, что механизм не заменяет уже плохой ход более сильным: первоначальная идея независимого раннего выбора могла случайно усиливать слабого бота.

## Проверка

Расширение до 18 фиксированных позиций: добавлены пешечная оппозиция с несколькими ходами, продолжение ловушки Блэкберна, давление на связанного защитника, центральная вилка. Старый forced fixture сохранён именно как проверка единственного легального хода. Повторно получены реальные кандидаты и независимый более глубокий анализ Stockfish 19.

Сравнение с замороженным опубликованным selector-v18: 3000 выборов на позицию, 54000 на Elo для каждой версии; 8 Elo (включая 474 для пользователя 574), всего 864000 выборов, seed 20260912. Старый selector используется исключительно инструментом симуляции. Данные двух версий одинаковые. Отдельные регрессионные проверки используют ещё seed 7 и 91. При Elo 474 в позиции black-tactical лучший нематующий h7h5 выбирался 825 раз из 3000, теперь 56. В several-good Nh4 с ранним loss 0.55 и глубоким 2.52 выбирался 148 раз, теперь 870. В pinned-defender Qa4 с ранним loss 0.81 и глубоким 1.54: 120 → 745. Это примеры поведения на фиксированных позициях, не обещание человеческого Elo.

Ранние оценки выявили подходящие варианты только в двух из 18 позиций. Stockfish даже при небольшой глубине использует тактическое доисследование. Поэтому механизм ограниченный и не заменяет остальные категории ошибок. Матовая гипотеза «если пропустил мат в 2, перестал видеть все маты» не вводилась: в fixture ферзь против короля почти все ходы по-прежнему сохраняют форсированный мат.

На одинаковых исходных 14 FEN среднее время анализа было 254.0 мс, в повторном прогоне 263.8 мс. Это замеры Node/WASM на рабочей машине, не Safari; различие отражает в том числе условия выполнения. Число поисков осталось одним.

## Ошибка на скриншоте

Восстановленная позиция: `4k1nr/p6p/5p2/3p3p/5P1b/4p3/1K2q3/8 w - - 0 34`. Права рокировки, halfmove clock и история повторений неизвестны. Движок нашёл шесть легальных ответов на шах и вернул ход примерно за 39 мс в локальном прогоне. Сбой телефона не воспроизведён, причина не установлена.

Добавлена защита от отдельного известного условия: при отсутствии полного MultiPV клиент может принять фактический bestmove движка, проверив легальность chess.js. Это не случайный ход; он может оказаться сильнее целевого, но позволяет продолжить игру. При timeout, сбое Worker или нелегальном bestmove остаётся окно ошибки с повторным расчётом. Не заявляется, что этот fallback исправляет конкретный сбой со скриншота.

## Экспорт

Кнопка «Экспорт PGN» расположена под списком ходов, доступна в текущей партии, при просмотре завершённой и в окне ошибки AI. Экспортирует полную партию, даже если пользователь сейчас смотрит более ранний ход. На поддерживаемых устройствах открывается системное меню передачи файла; иначе скачивается .pgn.

В PGN входят ходы, текущий FEN, цвета, рейтинги, результат, версия приложения, доступные model/target/effective Elo/seed. При последней ошибке для текущей позиции добавляются сообщение и FEN ошибки. Ошибка хранится только в памяти текущего открытия страницы и не отправляется автоматически. Архив новых партий сохраняет профиль бота, миграция его сохраняет после перезапуска. Для старых архивных партий недостающие параметры не выдумываются.

Телеметрия не добавлена. PGN передаётся только по действию пользователя. Локальное сохранение последнего сообщения не переживает перезагрузку. Stockfish worker сам по себе может сообщить только общий Worker failed, поэтому экспорт не гарантирует точную причину низкоуровневого сбоя.

Воспроизведение: npm run simulate:collect; node scripts/simulation/perception.mjs; npm run simulate; npm test. Приложение и офлайн-кэш v19. Дополнительно проверены round-trip PGN для текущей партии и нестандартного начального FEN, результат сдачи/ничьей, сохранение исходного объекта игры, легальный и нелегальный bestmove при неполном MultiPV и позиция со скриншота.
