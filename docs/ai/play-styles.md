# GachaChess: игровые профили, первая итерация

Реализация версии 0.2-v22. Анализ и план до изменения кода: [play-styles-plan.md](play-styles-plan.md).

## Архитектура

Существующая цепочка сохранена:

Позиция и история → Stockfish 19 MultiPV → легальные кандидаты, оценка, loss и ранний снимок → seeded Elo humanization (категория качества, fallback, guard, пропущенная тактика) → **ограниченный выбор стиля** → ход.

Effective Elo по-прежнему определяется один раз при создании партии. Настройки поиска одинаковы для всех стилей: 32 MultiPV или число легальных ходов, depth 9 / 150000 nodes, интерактивный movetime 2500 мс. Нет дополнительного поиска на кандидата. Skill Level 20, UCI_LimitStrength false. Дебютной книги нет; прежний opening multiplier ошибок сохранён.

В старом API `engineProfile` означает настройки силы. Внутри него добавлено единственное публичное поле `profile`, чтобы не переименовывать сохранённые партии и не дублировать сервис Stockfish.

```js
// Создать игровую сессию с существующим расчётом Elo и session variance:
const match = createStartedGame(state, Math.random, {profile: 'aggressive'});

// Существующий низкоуровневый API силы, первый аргумент — рейтинг ИГРОКА:
const engineProfile = createDifficultyProfile(
  1000, seededRandom(42), undefined, {profile: 'positional'}
);
client.postMessage({id, fen, pgn, engineProfile});
```

`profile`: `aggressive`, `solid`, `positional`, `tricky`. Отсутствующее значение или `default` возвращает исходный выбор без нового RNG и без анализа признаков. Неизвестное значение отклоняется. Поле сохраняется существующими state/archive-механизмами; PGN получает `BotPlayStyle`. Выбора персонажей в интерфейсе эта задача не добавляет.

## Ограничение силы

Сначала старая модель выбирает baseline. Затем формируется множество E:

- исходные оценённые кандидаты, без генерации новых ходов;
- та же категория качества, что у baseline;
- разница loss с baseline не больше **0,15 пешки**;
- тот же mate score / расстояние до мата;
- тот же статус tactical guard.

Если E содержит один ход, сохраняется baseline. В остальных случаях с вероятностью **0,45** выполняется взвешенный выбор в E, иначе baseline сохраняется. Веса:

`weight(c) = exp(2.5 × (styleScore(c) − maxScore(E)))`.

`styleScore = Σ coefficient(feature) × feature`.

Seed стиля: существующий seed партии XOR `0x5354594c`, затем существующий positionSeed по FEN и Mulberry32. Он отделён от потока Elo: стиль не меняет session variance, вероятность распознавания мата, выбор категории или срабатывание восприятия тактики. Одинаковые позиция, оценки, профиль и seed воспроизводят выбор. Повторный выбор может вернуть baseline.

Категории прежние: best <0,15; good <0,40; inaccuracy <0,90; mistake <1,80; blunder ≥1,80. Стиль **не** создаёт новое решение «ошибиться». Характер уже разрешённой ошибки меняется через предпочтения внутри узкого диапазона потери оценки. Например Reina может выбрать более активную неточность; Silas — улучшение пешечной структуры из разрешённых неточных вариантов. При единственном подходящем кандидате характер ошибки не меняется.

## Фактические коэффициенты

Положительный коэффициент предпочитает увеличение признака, отрицательный — уменьшение. Неиспользуемых параметров «на будущее» нет.

| Профиль | Атака | Безопасность | Позиция | Сложность | Размен |
|---|---:|---:|---:|---:|---:|
| Reina / aggressive | 1 | −0,25 | 0,15 | 0,65 | −0,65 |
| Bastion / solid | −0,15 | 1 | 0,25 | −0,65 | 0,8 |
| Silas / positional | 0,1 | 0,15 | 1 | 0,05 | 0,1 |
| NIX-7 / tricky | 0,35 | −0,15 | 0,1 | 1 | −0,8 |

Признаки вычисляются на копии позиции, не изменяя игровую историю:

- **Атака:** шах (0,6), приближение перемещённой фигуры к королю / 3, изменение доли атакованных полей вокруг короля соперника.
- **Безопасность:** уменьшение опасности вокруг своего короля; уменьшение стоимости атакованных и незащищённых фигур / 9; бонус рокировки 0,35.
- **Позиция:** изменение оценки пешечной структуры / 3 плюс изменение центральной активности и продвижения пешек / 3. Сдвоенная пешка −0,5, изолированная −0,5; проходная +1 с добавкой за продвижение. Центральность — геометрическая, не новый шахматный движок.
- **Сложность:** 0,5 × число легальных ответов / 40 + 0,5 × число взятий и шахов в ответах / 8 + 0,25 при сохранении обоих ферзей − величина размена.
- **Размен:** номинал взятой фигуры / 9. Отдельно для диагностики распознаётся прямое Q×Q.

Признаки ограничены диапазоном [−1,1]. Материал: пешка 1, конь/слон 3, ладья 5, ферзь 9. Определение атак chess.js геометрическое; связанная фигура может числиться атакующей. Сложность использует **легальные**, а не доказанно хорошие ответы. NIX-7 не получает будущий ответ игрока и не предсказывает, что тот заметит.

## Изменённые модули

- `dist/play-style-config.js`: значения профилей, предел влияния, валидация.
- `dist/play-style.js`: признаки, envelope, детерминированное взвешивание.
- `dist/difficulty-model.js`, `session.js`, `strength.js`: опциональное назначение профиля с сохранением старого API и seed.
- `dist/stockfish-client.js`: вызов стиля после существующей humanization, включая восстановление после timeout.
- `dist/pgn-export.js`: профиль в экспортируемой партии.
- `dist/sw.js` и версии импортов: офлайн-доступ новых модулей.
- `tests/play-style.test.js`, `humanized-client.test.js`: unit и реальный adapter.
- `scripts/simulation/play-styles.mjs`, `summarize-play-styles.mjs`, `play-style-performance.mjs`: локальная проверка, без production telemetry.

## Методика

1. Те же 18 зафиксированных позиций и кандидаты текущего бюджета из `search-budget.json`: дебюты, тактика, связка, тихие позиции, выигрыш/проигрыш, маты, эндшпили. 1000 seed на позицию, 4 Elo × 5 вариантов (default + 4 профиля) = **360000 выборов**. Сравнение с baseline на абсолютно одинаковом исходном выборе категории. Дополнительно попарное сравнение стилей с одинаковыми seed.
2. Реальные партии через текущий SF19 adapter: все 6 пар, Elo **600/1000/1400/1600**, по 2 seed × смена цветов = **96 партий**. Начальная позиция обычная, дебютной книги нет; variance выключена для прямого сравнения одного effective Elo. Seed 20260913 и 20261922. Четыре независимых процесса двигателя, один поиск на ход. Depth/node budget production; без movetime для воспроизводимости. До 240 полуходов; незавершённые партии имеют результат `*`, а не объявляются ничьей.
3. CP loss считается только в позициях, где все сравниваемые оценки CP. Mate utility не называется centipawn loss. Это оценка текущего ограниченного поиска, не независимый глубокий судья; для фиксированных позиций дополнительно сохранён reference utility loss прежнего глубокого анализа.
4. Сохраняются W/D/L и незавершённые партии, CP loss, rank, взятия/шахи, пары снятых ферзей, материал после 40 полуходов, разнообразие выбора в повторяющихся позициях, доля замен baseline и PGN всех игр. Queen exchange pairs означает, что обе стороны потеряли ферзя; это более широкий показатель, чем немедленный Q×Q.

## Выводы и ограничения

1. **Elo envelope работает.** На одинаковых позициях каждый стиль сохранил категорию исходного выбора; максимальное различие среднего CP loss от default — 0,311 cp. С ростом Elo CP loss уменьшался у всех четырёх профилей. Это подтверждает локальное ограничение качества, но не равенство турнирного рейтинга.
2. **Профиль действительно влияет на выбор.** На фиксированных позициях меняются 15–23% ходов относительно baseline, в партиях 12,5–16,1%. По одинаковым seed Reina/Bastion различаются сильнее, Silas/NIX-7 — слабее. Последние пока имеют более тонкие отличия, особенно на 600 Elo. Отдельная регрессионная проверка подтверждает рост собственного стилевого score каждого профиля на независимом наборе seed.
3. **Точного баланса по результатам партий не доказано.** Общий результат Reina — 41,7% очков в завершённых партиях против 48,9–54,5% остальных. Особенно заметен результат Reina на 1600 (25%), при положительном результате на 1400 (65%). На каждом уровне всего 12 партий на профиль, а 8 партий турнира не завершились. Это сигнал для расширенного парного турнира, а не основание объявить профили равными или подгонять коэффициенты под два seed.
4. **Высокоуровневые обещания стиля подтверждены лишь частично.** На общей игровой выборке Reina не дала больше шахов, чем Bastion; NIX-7 не стал лидером метрики разнообразия повторных позиций. Эта метрика дополнительно ограничена одинаковыми seed: повторение одной позиции с тем же seed намеренно воспроизводит ход. Первая версия реализует предпочтения конкретных признаков, не полноценные человеческие личности. Нельзя считать рост внутреннего style score независимой шахматной экспертизой.
5. **Геометрические признаки ограничены.** Сближение с королём не означает реальную атаку: пешка может приблизиться через закрытую структуру. Проходные/центральность не заменяют стратегической оценки; legals/forcing replies не доказывают практической трудности. Все эти предпочтения защищены пределом 15 cp и неизменной категорией качества.
6. **Высокие рейтинги:** 1800 не тестировался и не выдаётся за поддерживаемый уровень. Текущая система ограничена 1600. Native strength и новую Elo-калибровку эта работа не добавляет.
7. **Воспроизводимость:** выбор при одинаковых оценках и seed детерминирован. Stockfish на другом устройстве при movetime или timeout может вернуть другой набор кандидатов. Турнир использовал фиксированный node/depth budget без movetime; тесты отдельно подтверждают реальный adapter и существующее восстановление Worker.
8. **Производительность:** дополнительных поисков нет, default не вычисляет признаки. Desktop/Node замер не является проверкой плавности интерфейса Safari; при публикации полезна отдельная проверка на устройстве.

Коэффициенты после скрининга оставлены исходными для этой реализации: категориального перекоса или нарушения легальности не найдено; игровая выборка недостаточна для надёжной коррекции отдельно Reina. Дополнительный пересмотр силы без подтверждения противоречил бы разделению Elo и стиля.

## Следующая итерация — рекомендации, не реализованы

- Увеличить число парных seed прежде всего для Reina 1600 и проверить партии независимым более глубоким анализом. Отделить позиционную силу от последствий выбора другого дерева игры; учитывать незавершённые партии отдельно.
- Для Silas/NIX-7 добавить экспертно подобранные позиции с явным стратегическим планом и практической сложностью; сравнить условную энтропию выбора по разным seed на одинаковой позиции. Затем решать, стоит ли усиливать признаки, не увеличивая envelope.
- Улучшить оценку фактического давления на короля вместо одной геометрической близости. Подтверждать изменения человеческой шахматной проверкой примеров.
- Отдельно спроектировать Opening Model с теми же стабильными `profile` ID. Сейчас нет искусственной дебютной книги, openingPreferences-заглушек или зависимости от поведения пользователя.
