# Восстановление поиска и снижение нагрузки

## Что изменено

Клиент использует 32 PV, глубину 9 и 150000 узлов вместо глубины 10 и 500000 узлов. Сохранена ширина вариантов: сокращается вычислительный бюджет, а не набор кандидатов до идеальных ходов.

Интерактивный movetime 2500 мс. На 3500 мс клиент просит stop. На 5000 мс отсутствие bestmove запускает восстановление:
1. Берётся последний полный согласованный MultiPV-пакет. При наличии используется обычная Difficulty Model и тот же position seed.
2. Если полного пакета нет, берётся последний полный одиночный PV с multipv=1. Это реальная оценка Stockfish, не случайный легальный ход. При одном кандидате бот может сыграть сильнее целевого.
3. Выбранный ход проверяется chess.js. Если данных нет или они не дают легального хода, остаётся ошибка. Без данных выдумывать ход нельзя.
4. Перед выдачей восстановленного хода текущий Worker уничтожается, его идентичность сбрасывается, таймеры очищаются. Следующий запрос лениво создаёт новый Worker и проходит uci/isready. Сообщения и ошибки старого Worker игнорируются по идентичности экземпляра. Они не могут стать ответом на новую позицию.

Инициализация имеет отдельный 60-секундный watchdog. Эти сроки зависят от планирования браузера; замороженная вкладка не гарантирует выполнение JS-таймера в точный момент. Возврат fallback не устраняет зависание низкоуровневого движка, но позволяет продолжить игру, когда промежуточный анализ уже был получен.

Для analysisOnly сохранён отдельный 15-секундный защитный watchdog и узловой бюджет без movetime по умолчанию. Внешний интерфейс клиент→приложение не изменён. Пересоздание Worker происходит внутри существующего адаптера. Телеметрии нет.

## Сравнение бюджетов

Реальный Stockfish 19 WASM, 18 фиксированных позиций, одинаковые независимые глубокие reference evaluations. На каждый бюджет: 1000 выборов на позицию и каждый из 8 Elo (400,474,600,800,1000,1200,1400,1600), 144000 выборов. Seed 20260912.

| Бюджет | Среднее время | Максимум | Среднее число кандидатов |
|---|---:|---:|---:|
| depth 10 / 500000 nodes | 310 мс | 658 мс | 23.44 |
| depth 9 / 150000 nodes | 126 мс | 203 мс | 23.44 |
| depth 8 / 80000 nodes | 80 мс | 149 мс | 23.44 |

Выбран второй вариант: среднее время уменьшилось примерно на 60%, число кандидатов сохранено. На 600 Elo independent-reference Best+Good изменился с 58.08% до 57.60%, reference loss с 2.016 до 2.103 (включает mate utility). Более дешёвый третий вариант давал 60.48% Best+Good — слабый бот становился сильнее по этому показателю, поэтому он отклонён. На высоких Elo более короткий анализ тоже снижает качество: например, Best+Good 1600 по reference 91.28% → 85.39%. Это компромисс производительности, не калибровка человеческого Elo.

Для выбранного бюджета сохранение порядка силы по reference loss проверено ещё на seed 7 и 91 и автоматизировано как регрессионный тест. Сохраняется восемь строго упорядоченных Elo. На каждом FEN число кандидатов равно min(32, legalMoves). Старые результаты simulation.json отражают прежний глубокий бюджет; актуальное сравнение бюджетов находится в results/search-budget.json. Исходные данные включены для воспроизведения.

## Проверки отказов и партии

118 тестов прошли. Покрыты stop до аварийного срока, ответ после stop, отсутствие данных, нелегальный промежуточный PV, полный пакет, одиночный промежуточный PV, создание следующего Worker, запоздалые bestmove/readyok/error старого Worker, отмена таймеров. Реальный экземпляр Stockfish прошёл последовательность исходного PGN и ещё 20 полуходов. Эти проверки выполнялись в Node/WASM, не в Safari.

Браузерный сценарий подготовлен в scripts/browser-worker-check.html: семь позиций по исходному PGN, затем до 20 полуходов продолжения через тот же браузерный Worker. Запуск: node scripts/serve-worker-check.mjs, открыть напечатанный локальный URL и нажать «Проверить Worker». Сервер выставляет COOP/COEP, не публикует сайт.

Проверка в облачном Chrome не завершена: доступ к локальному тестовому серверу отклонён с ERR_BLOCKED_BY_CLIENT. Локального Chromium в среде не было; загрузка браузерного пакета также не удалась. Обход сетевого ограничения не выполнялся. Поэтому конкретный сбой iPhone всё ещё не воспроизведён, и браузерное исправление не объявляется окончательно подтверждённым.

Воспроизведение: npm test; node scripts/simulation/search-budget.mjs. Изменения остаются локальными до отдельного разрешения на публикацию. PWA v21 (предыдущая локальная версия v21 ещё не публиковалась).
