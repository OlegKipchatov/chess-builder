# Cognitive 2.1 — реализация технических окончаний

## Поставка

- Идентификатор поведения: `cognitive-v2.1-conversion-1`.
- Runtime/cache revision: `v32`.
- Семейство профиля остаётся `cognitive-v2`; это существующий транспортный id, не выбор старой версии.
- Все текущие cognitive-партии сразу используют 2.1. При загрузке активного профиля обновляется calibrationVersion; seed и Elo не пересоздаются. Отдельной 2.0-ветки для старых партий нет.
- Завершённые архивы не переписываются.
- Native Stockfish по-прежнему выбирается при targetElo >= 1400.
- Опубликованная версия не меняется до отдельного разрешения на публикацию.

Это документ фактической реализации. Требование сохранять старое поведение для активных партий из первоначальной спецификации отменено пользователем.

## Область действия

Режим работает только для сильной стороны с ладьёй/ферзём против голого короля, без пешек, до шести фигур включительно. В остальных позициях используется обычный cognitive-поиск с прежними таблицами способностей. Сигнатура не является доказательством выигрыша конкретной позиции.

Новые модули:

- `conversion-config.js`: параметры режима.
- `conversion-board.js`: SAN-free адаптер к поставляемому chess.js.
- `conversion-model.js`: признаки и оценка.
- `conversion-history.js`: повторы и отсутствие прогресса.
- `conversion-search.js`: безопасность, корневой набор, minimax и выбор.

## Поведение

- Корневой набор строится из всех легальных ходов, без вероятностного исключения тихих ходов старым candidateIdeas.
- Мат в один выбирается детерминированно до softmax.
- Пат, немедленная ничья и отдача последней тяжёлой фигуры исключаются при наличии проверенной непосредственной безопасной альтернативы.
- Все легальные ответы защищающегося короля входят в поиск. Внутренние ходы сильной стороны ограничены beam=4.
- Корень ограничен восемью ходами, с резервированием тихих ходов и приближения короля.
- Полностью завершённая глубина общая для всех выбираемых корневых ходов. Частичная итерация отбрасывается.
- Базовая глубина — четыре полухода от root, включая первый ход. После шести собственных ходов без нового прогресса или при halfmoveClock >=70 целевая глубина повышается до шести.
- Бюджеты — 3000/6500 операций поиска и ordering. Обязательный конечный safety-preflight считается отдельно. Явные maxNodes/maxDepth остаются верхними ограничениями.
- Повторы учитываются по истории и текущей ветви, независимо от внутренних счётчиков chess.js.
- Случайность ограничена близкими оценками. После трёх собственных ходов без прогресса выбор становится детерминированным; профиль не может предпочесть худший исход доказанному мату.

`conversionEnabled: false` — аварийное выключение узкого режима, не механизм поддержки старых игровых сессий. Вне режима единственный обычный cognitive-поиск остаётся нужен для остальных позиций.

## Изменения относительно исходной технички

Первоначальная локальная метрика плохо отличала короля в большой области доски от короля в маленькой: число соседних безопасных клеток могло быть одинаковым. В проверках это давало слишком длинные ладейные окончания и отдельную ничью по 50 ходам. Простое увеличение глубины также повышало стоимость, часто не завершая новую итерацию.

Добавлен `cage`: 1 − площадь связной безопасной области / 64. Область вычисляется flood-fill по пустым неатакованным клеткам после удаления слабого короля из геометрии лучей. Занятые клетки считаются границами: это эвристика ограничения пространства, а не точное доказательство недоступности после будущих взятий. Взятия проверяются легальными ответами в поиске.

Финальная стартовая оценка прогресса:

```text
P = 0.50 × cage
  + 0.20 × edgePressure
  + 0.20 × kingProximity
  + 0.05 × confinement
  + 0.05 × coverage

technicalScore = 360 × (0.45 + 0.55 × conversionSkill) × P
```

Весовые коэффициенты находятся в замороженном featureWeights. Мобильность короля рассчитывается на виртуальной доске с учётом открытия линий после ухода/взятия. Признаки кэшируются по позиции; исторически зависимые результаты поиска не кэшируются только по FEN.

Температура conversion составляет 0.30 от обычной, а не первоначальные 0.60. Допустимое отставание от лучшей оценки уменьшается с отсутствием прогресса. Эти параметры — проверенные на ограниченном корпусе инженерные настройки, не калибровка человеческого Elo.

Исторический лучший P не сбрасывается простым колебанием вниз-вверх. После смены материальной сигнатуры история прогресса начинается заново. Штраф не суммируется повторно на каждом уровне дерева.

## Адаптер chess.js

Чтобы не рассчитывать SAN и матовый суффикс для каждого внутреннего кандидата, адаптер использует `_moves`, `_makeMove`, `_undoMove` поставляемого chess.js. Это сознательная зависимость от конкретной vendored-версии, изолированная в одном файле. Контрактные тесты сравнивают наборы ходов и состояния с публичным API, включая восстановление после исключения.

Private make/undo не изменяют внутренние repetition counts. Новый поиск не использует isThreefoldRepetition для воображаемых ветвей: отдельный counts учитывает PGN и каждый make/undo. Mate имеет приоритет над halfmove-ничьёй. Обновление chess.js требует повторной проверки адаптера.

## Проверки и воспроизведение

```sh
npm run prepare:engine
npm test
npm run simulate:conversion -- --wide
npm run simulate:conversion -- --generated
```

- `--wide`: пять начальных окончаний × три уровня × четыре seed = 60 партий.
- `--generated`: пять основных плюс 20 детерминированно сгенерированных позиций, уровень 840 и incident seed = 25 партий.
- Защита: Stockfish 19, depth 12 / 80000 nodes / 250ms. Это сильная ограниченная защита, не tablebase oracle. Ответы могут зависеть от доступного времени.
- Stockfish присутствует только в отдельном simulation-скрипте и не передаёт оценки/кандидатов production-модели.
- Результаты, PGN, последний trace, config и SHA-256 исходных модулей: `docs/ai/results/conversion-v2.1/matrix.json` и `generated.json`.
- 18 замороженных обычных решений сравниваются с предыдущей ревизией, включая детерминированные trace-поля кроме версии.
- Unit/integration-тесты покрывают mate-in-one, пат, потерю тяжёлой фигуры, третье повторение, исчерпание бюджета, симметрию, мобильность, переключение активных сессий и native-routing.

Эти серии не доказывают 99% надёжность на произвольных окончаниях. Корпус для настройки и небольшой generated-набор не заменяют независимый масштабный holdout и tablebase-проверку. Позиции с почти исчерпанным halfmoveClock могут быть уже невыигрываемыми; обещания гарантированного мата в них нет.

### Результаты финального прогона 2026-09-22

| Проверка | Результат |
|---|---|
| Матрица 3 уровня × 4 seed × 5 окончаний | 60/60 матов |
| Основные + 20 generated-позиций | 25/25 матов |
| Пат / повторение / ничья по 50 ходам | 0 в обеих сериях |
| Инцидент, матрица | максимум 27 полуходов |
| KRK, матрица | p95 53, максимум 59 полуходов |
| KQK, матрица | p95 31, максимум 37 полуходов |
| Node latency, матрица | p50 74 мс, p95 183 мс, максимум 406 мс |
| Node latency, generated | p50 71 мс, p95 177 мс, максимум 363 мс |

Хеши модулей в обоих отчётах сверены с финальными исходниками. Пять базовых позиций повторяются между сериями; 85 партий не означают 85 независимых начальных позиций. В матрице использован стиль solid; остальные стили дополнительно проверяются на легальность и детерминизм unit-тестами, но не отдельными полными матрицами.

## PWA и ограничения проверки

Все URL JS/CSS, включая вложенные импорты, согласованно обновлены до v32; новые модули включены в precache. Автотест имитирует переход v31 → v32, принудительную загрузку ресурсов без HTTP-кэша и удаление только старого кэша приложения. Это не проверка установленной PWA на реальном телефоне. Перед публикацией нужно проверить реальный переход и latency мобильного Worker.

Число узлов не включает стоимость mandatory safety-preflight и восстановления PGN; время решения в симуляциях включает их. Приведённые отчёты измеряют Node, не мобильный Safari.
