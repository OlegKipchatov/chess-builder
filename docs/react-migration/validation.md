# React migration validation

Baseline: v132, `ee7df974635bf7dd514c24e4d4a6b04bce3af8c6`.
Migration branch: `migration/react-architecture-20261017`.

## Scope and ownership

All first-party application rendering is React; no legacy HTML-template bootstrap, old navigation controller or embedded vanilla UI remains. `dist/` is ignored generated output. The original implementation remains in the baseline commit and is extracted unchanged for installed-PWA upgrade tests. Upstream chess.js and pinned Stockfish 19 runtime assets remain third-party dependencies.

| Layer | Responsibility |
|---|---|
| `src/app` | Persistent providers, bootstrap, TanStack Router and application shell |
| `src/pages` | Game, collection, chests, history/import/review, activity/streak, profile, statistics, FAQ, Hunt, Autochess and PvE composition |
| `src/features` | Game session, memoized chessboard, playback/training, inventory commands and mode orchestration |
| `src/domain` | Typed chess, rating, economy, collection, activity, analysis, Cognitive AI and mode rules; no React/browser dependencies |
| `src/services` | Transactional persistence, engine/analysis lifecycle and release-scoped service worker |
| `src/workers` | Stockfish, Cognitive AI and PvE computation |
| `src/shared` | Accessible UI, SVG assets, hooks, types and semantic style/motion tokens |

Saved state uses narrow `useSyncExternalStore` subscriptions and structural sharing. Feature hooks/reducers own transient state and asynchronous transitions; Context supplies services and stable ownership. The vault serializes transactions and persists before notifying React. There is no Redux/Zustand dependency. See [architecture](../architecture.md) for hook and Worker boundaries.

Hash routing supports GitHub Pages refresh and direct links without server rewrites. Routes are lazy-loaded through TanStack Router; game state survives navigation. TanStack Virtual applies to archives over 50 items. TanStack Start/SSR adds no current hosting or offline benefit, so this release is a Vite SPA without hydration or a mandatory server.

## PWA checks

The upgrade harness starts with the real v132 HTML, service worker and caches, including an active saved game. It rejects one new asset to prove that a failed update leaves the old release usable, retries, then accepts the update through the old Profile action. It checks preserved progress, exact previous Worker URLs, unrelated caches and cold offline reopening. The same workflow runs with isolation disabled for the single-thread fallback.

The custom TypeScript service worker uses `injectManifest`, precaches lazy chunks and engine assets as one release, and serves installed HTML with matching chunks. Update activation is explicit and defers reload through active play/modal state. It never clears localStorage or IndexedDB. See [PWA deployment](../pwa-deployment.md).

## Performance and limitations

Bundle measurements are in [bundle-report.json](bundle-report.json). Browser samples, medians and methodology are in [performance-browser.json](performance-browser.json). Initial JS/CSS excludes lazily initialized engines/modes; full release size includes their local runtime assets.

The initial route preload correction removed an import/render waterfall. The earlier measurements are retained in [performance-before-route-preload.json](performance-before-route-preload.json). The final application code measured as follows (median milliseconds):

| Viewport | Ready, v132 → React | Start to paint, v132 → React | Move to persisted paint, v132 → React |
|---|---|---|---|
| 390 px | 186.6 → 144.7 | 26.0 → 30.6 | 21.4 → 38.2 |
| 1280 px | 181.1 → 142.2 | 25.7 → 32.0 | 21.7 → 38.2 |

Startup improved by 21–22%. The move path costs another 16.5–16.8 ms (about one 60 Hz frame); this is a measured regression, although the animation duration remains unchanged. No React main-thread task over 50 ms appeared in these ten samples; another preceding run had one 56 ms task, so this is not a guarantee under all loads. Initial JS/CSS requests fell from 106 to 16 in the measured first-screen flow. Initial JS/CSS is 521,211 raw bytes / 166,582 gzip bytes versus 606,237 / 196,904 in v132: a 15.4% gzip reduction. The full local runtime is 4,407,788 bytes. Board movement stays 420 ms; reduced motion and PvE phase timing have separate behavioral checks.

Browser evidence uses Chromium 151 on Linux with mobile viewport/touch and safe-area simulations. These are not physical iOS/Android, Safari or Firefox certification, real-network performance measurements, or long-session battery/memory measurements. The managed authoring environment has no permitted local `control-browser`; browser execution runs in GitHub Actions.
